# SEO / AEO / GEO Audit — Doshhmukti (doshmukti.com)

## Executive Summary
Site foundation strong — someone already did real SEO work here (per-page JSON-LD, revalidating sitemap w/ product URLs, AI-crawler-aware robots.txt, self-contained FAQ answers, llms.txt). Biggest gap: **homepage has zero `<h1>`** — hurts both classic ranking and AEO/GEO entity signal on the single highest-authority URL on the site. Second gap: title/description tags on 3 core pages run 1.4-4x over SERP display length, so Google truncates them mid-sentence. Quick wins fix both in under a day.

## Scope & Inputs
Reviewed via repo code (not live-fetched): `robots.ts`, `sitemap.ts`, root `layout.tsx`, homepage, `/shop`, `/products/[slug]`, `/faq`, `/about`, `/vahan-suraksha-kavach`, `next.config.ts`, `public/llms.txt`. Not assessed: actual Core Web Vitals field data (no live crawl/PSI run), backlink profile, live SERP truncation screenshots.

## Findings

### Technical SEO — Good
- ✅ `robots.txt` correctly allows crawl, blocks `/cart /checkout /profile /orders /login /api/`, references sitemap, and explicitly allows `GPTBot ChatGPT-User PerplexityBot ClaudeBot Google-Extended` etc. — rare to see this done deliberately.
- ✅ `sitemap.ts` revalidates hourly (fixes a real past incident — comment notes a build-time Backend outage silently dropped all `/products/*` from the live sitemap). Includes static routes, purpose-filtered `/shop` URLs, and all product slugs.
- ⚠️ **`/vahan-suraksha-kavach` is an orphan page** — canonical set, has metadata, has an `<h1>`, but zero internal links to it anywhere in the codebase and it's not in `sitemap.ts`'s `STATIC_ROUTES`. If this is a paid-traffic-only landing page, that's likely intentional (keeps it out of organic index/dilution) — confirm intent; if it's meant to rank organically, it needs a sitemap entry + at least one internal link (e.g. from a "Protection" category or footer).
- No evidence of redirect chains, broken links, or mixed content in the code reviewed — recommend a live crawl (Screaming Frog / Search Console Coverage report) to confirm, since these are runtime issues code review can't fully catch.

### On-Page SEO — Needs Work
- 🔴 **Homepage has no `<h1>` anywhere** — checked `page.tsx` and every child component it renders (`HeroCarousel`, `PurposeGrid`, `CategoryStrip`, `ProductRail`, `AcharyaMadhavSection`, `TestimonialsCarousel`). Zero `<h1>` tags found. This is the single most-linked, highest-authority URL on the domain running with no primary heading — a real ranking and AEO/GEO cost. **Fix**: add a visually-styled `<h1>` in the hero (can be the tagline already in `TITLE_DEFAULT`, shortened) — doesn't have to be ugly, just present in markup.
- 🔴 **Homepage title tag too long**: `"Doshhmukti — Dosh Mukti Gemstones & Astrology Remedies for Love, Wealth & Protection"` — 86 chars. Google truncates around 60. Rewrite to something like `"Doshhmukti — Gemstones & Astrology Remedies for Love & Wealth"` (~63) or tighter.
- 🔴 **Homepage meta description too long**: current one is ~247 chars vs. the ~155-160 Google displays — the back half (`"Shop remedies for love, wealth, health, success, protection and clarity"`) never shows. Trim to the strongest 155 chars.
- ⚠️ **About page title is redundant**: `"About Doshhmukti — Authentic Astrology-Guided Gemstones"` + the layout's `%s — Doshhmukti"` template = `"About Doshhmukti — Authentic Astrology-Guided Gemstones — Doshhmukti"` (68 chars, brand name appears twice). Either drop "Doshhmukti" from the page-level title or don't use the template on this page.
- ✅ Product, Shop, and FAQ page titles/descriptions are properly scoped per-entity and reasonably sized.
- ✅ Purpose-filtered `/shop?purpose=X` URLs get unique title/description per purpose — good long-tail coverage for "gemstones for wealth" style queries.
- ⚠️ `HeroCarousel` banner images use `alt=""` (decorative) — correct *if* the banner is purely visual, but if any banner image carries promotional text baked into the image (common for hero carousels), that text is invisible to crawlers and AI extractors. Confirm whether banner copy exists as real HTML text anywhere, or only inside the image.
- ✅ Product/category/thumbnail images elsewhere have descriptive `alt` text (`${name} — photo ${i+1}`, `${name} thumbnail ${i+1}`) — good pattern, keep it consistent.

### AEO (Answer Engine Optimization) — Strong
- ✅ `/faq` is a model AEO implementation: each Q is a real search-style question, each A is 1-3 self-contained sentences with the answer stated first (own comment in the code literally says "snippet- and LLM-extractable"), and `FAQPage` JSON-LD matches the visible text exactly (no mismatch risk).
- 🟡 **Missed opportunity**: product pages have a real numbered "How to Wear & Recharge" step list (`<ol>`, real step content) but no `HowTo` schema on it. This is a clean, low-effort snippet target — "how to wear a [gemstone] bracelet" is a real query pattern. Add `HowTo` JSON-LD per product where `howToWear` is populated.
- 🟡 No `Speakable` schema anywhere — low priority (limited rollout) but free to add to FAQ/homepage given the content already qualifies.
- Homepage's missing `<h1>` (above) is also an AEO problem — extraction algorithms lean on heading hierarchy to find the "what is this page about" anchor.

### GEO (Generative Engine Optimization) — Strong, Small Gaps
- ✅ `Organization` schema in root layout: name, url, logo, alternateName, `sameAs` to Instagram/YouTube, and a clean one-paragraph self-description — exactly what an LLM retrieval pipeline wants for entity grounding.
- ✅ `Person` schema for Acharya Madhav on `/about` establishes a named, credentialed authority (`jobTitle: Vedic Astrologer`) tied to the Organization via `worksFor` — real authority signal for GEO citation.
- ✅ `llms.txt` present at domain root — ahead of most sites on this.
- ✅ Product JSON-LD includes real customer review bodies server-rendered (per the comment in `page.tsx`, this was a deliberate fix so Googlebot's first pass sees actual review text, not just an aggregate score) — directly useful for GEO too, since it gives LLMs quotable, attributed customer statements instead of just a number.
- 🟡 `Person` schema for Acharya Madhav has no `image`, `url`, or `sameAs` — add a profile photo and a canonical URL (e.g. `${SITE_URL}/about#acharya-madhav`) to strengthen the entity.
- 🟡 Product JSON-LD has no `gtin`/`mpn`/`itemCondition`/`priceValidUntil` — not required, but each one is a small additional trust/completeness signal for both Google Merchant-style parsing and LLM product-fact extraction.
- ✅ AI crawlers explicitly allowed in `robots.txt` (already covered above) — this is the technical-access half of GEO and it's done right.

## Prioritized Action Plan

### Quick Wins (hours)
1. Add a real `<h1>` to the homepage hero.
2. Shorten homepage title to ≤60 chars, description to ≤160 chars.
3. Fix About page title/template duplication ("Doshhmukti" appearing twice).
4. Confirm hero banner images don't carry text-only promotional copy; if they do, mirror that text as real HTML (even visually hidden) near the banner.
5. Add `image`/`url` to the Acharya Madhav `Person` schema.

### Structural Fixes (days)
6. Add `HowTo` JSON-LD to product pages where `howToWear` steps exist.
7. Decide `/vahan-suraksha-kavach`'s intended status (paid-only orphan vs. organic page) and act accordingly — either link it in nav/footer + sitemap, or leave it deliberately unlinked and document that choice.
8. Add `CollectionPage`/`ItemList` schema to purpose-filtered `/shop?purpose=X` pages to reinforce them as distinct entities, not just filtered views.

### Strategic Investments (weeks+)
9. Live technical crawl (Screaming Frog or Search Console Coverage/Core Web Vitals report) to catch runtime issues code review can't — redirect chains, actual LCP/CLS/INP field data, real broken links.
10. Content depth pass: each purpose page (`love`, `wealth`, etc.) could carry its own short on-page educational blurb (not just product grid) to compete for informational queries, not just transactional ones — currently these pages are pure catalog with no unique body copy beyond the meta description.
11. Backlink/citation building — get Doshhmukti mentioned/linked from astrology or gemstone content sites; also raises GEO odds since LLM retrieval weights sites other sources reference.

## Schema Markup — Ready to Paste

**`HowTo` for product pages** (add alongside existing `productJsonLd`/`breadcrumbJsonLd` in `Frontend/src/app/(storefront)/products/[slug]/page.tsx`, only when `product.howToWear.length > 0`):

```json
{
  "@context": "https://schema.org",
  "@type": "HowTo",
  "name": "How to Wear & Recharge {{product.name}}",
  "step": [
    { "@type": "HowToStep", "position": 1, "text": "{{product.howToWear[0]}}" },
    { "@type": "HowToStep", "position": 2, "text": "{{product.howToWear[1]}}" }
  ]
}
```
(Map every entry in `product.howToWear` to a `HowToStep`, `position` = index + 1.)

**Updated `Person` schema for Acharya Madhav** (`Frontend/src/app/(storefront)/about/page.tsx`):

```json
{
  "@context": "https://schema.org",
  "@type": "Person",
  "name": "Acharya Madhav",
  "jobTitle": "Vedic Astrologer",
  "url": "https://doshmukti.com/about#acharya-madhav",
  "image": "https://doshmukti.com/images/acharya-madhav.jpg",
  "worksFor": { "@type": "Organization", "name": "Doshhmukti" },
  "description": "Acharya Madhav is Doshhmukti's in-house Vedic astrologer, recommending gemstones and remedies based on birth-chart (kundli) and numerology readings for love, wealth, health, career, and protection."
}
```

## Measurement & Reporting Plan
- **SEO**: Search Console — impressions/clicks/avg position for homepage + top purpose pages, weekly. Watch for CTR lift on homepage/about after title/description fixes (2-4 weeks to reflect in SERP, longer for ranking movement).
- **AEO**: Search Console "Search Appearance" filters for featured snippets where available; manual spot-check target queries ("how to wear a rudraksha bracelet", "gemstone for wealth") in Google monthly for AI Overview/snippet presence.
- **GEO**: No analytics product exists for this today — spot-check by asking ChatGPT/Perplexity/Claude/Gemini the target queries directly (e.g. "best gemstone for wealth astrology") monthly and note whether Doshhmukti is cited. This is manual, not a dashboard.
- **Re-audit triggers**: after the next deploy (re-check Core Web Vitals via PSI), and after Quick Wins ship (re-check title/description render in a live SERP screenshot).
